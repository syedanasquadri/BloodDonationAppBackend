# PART 1: FILE MAP

## Backend Files (`backend/`)

### Root & Configuration
- `backend/package.json` — defines backend dependencies, scripts (dev, build, test), and project configuration.

- `backend/tsconfig.json` — TypeScript compiler options for strict type-checking and NodeNext module output.

### Database & Migrations
- `backend/prisma/schema.prisma` — Prisma data model defining User, DonationRequest, Notification, Session, and PushToken.
- `backend/prisma/migrations/` — folder containing SQL schema migration files generated by Prisma Migrate.
- `backend/src/generated/prisma/` — folder containing auto-generated Prisma Client JavaScript and TypeScript artifacts.

### Server & Libraries
- `backend/src/server.ts` — initializes Express app, mounts routes, starts HTTP server, and attaches Socket.IO.
- `backend/src/lib/prisma.ts` — instantiates and exports the singleton PrismaClient with PostgreSQL database adapter.
- `backend/src/lib/geo.ts` — computes great-circle distance between two geographic coordinates using the Haversine formula.

### Authentication (`src/auth/`)
- `backend/src/auth/auth.middleware.ts` — verifies Bearer JWT on protected routes and attaches authenticated userId to res.locals.
- `backend/src/auth/auth.routes.ts` — defines authentication endpoints for OTP sending, verification, signup, refresh, and logout.
- `backend/src/auth/controllers/auth.controller.ts` — handles HTTP requests for sending/verifying OTP, completing signup, session refresh, and logout.
- `backend/src/auth/services/auth.service.ts` — generates 6-digit OTPs, hashes with SHA-256, verifies attempts, and manages expiration.
- `backend/src/auth/services/token.service.ts` — creates, verifies, and revokes JWT access tokens, signup tokens, and refresh sessions.

### Core Controllers & Routes (`src/controllers/`, `src/routes/`)
- `backend/src/controllers/user.controller.ts` — queries donors sorted by distance, gets/updates/deletes user profiles, and notifies on update.
- `backend/src/controllers/donationRequest.controller.ts` — creates donation requests with urgency and hospital, updates status, and lists sent/received.
- `backend/src/routes/user.routes.ts` — routes requests for donor search, user profile retrieval, update, and deletion.
- `backend/src/routes/donationRequest.routes.ts` — routes requests for creating, listing sent/received, and updating donation request status.

### Notification System (`src/notifications/`)
- `backend/src/notifications/notification.types.ts` — TypeScript interfaces and enums for notifications, preferences, push tokens, and query options.
- `backend/src/notifications/notification.repository.ts` — queries database for notifications, unread counts, push tokens, preferences, and idempotency deduplication.
- `backend/src/notifications/notification.service.ts` — orchestrates notification persistence, preference filtering, deduplication, and Socket.IO/Push dispatch.
- `backend/src/notifications/notification.controller.ts` — handles endpoints for push tokens, notification listing, marking read, deletion, and preferences.
- `backend/src/notifications/notification.routes.ts` — routes endpoints for push tokens, notification inbox, read receipts, and preferences.
- `backend/src/notifications/socket.service.ts` — manages Socket.IO connections, JWT authentication, user rooms, and real-time event broadcasting.
- `backend/src/notifications/expoPush.service.ts` — formats, batches, and sends push notifications to devices via Expo Push Service.

### Automated Test Suite (`test/`)
- `backend/test/donationRequest.test.ts` — unit and integration tests for donation request workflows, urgency, and hospital details.
- `backend/test/geo.test.ts` — unit tests for Haversine distance calculations and closest-first donor sorting logic.

### 4. Real-Time and Background Connections

- **Socket.IO Real-Time Messaging**:
  - **Backend Server**: `backend/src/notifications/socket.service.ts` initializes Socket.IO with Bearer JWT handshake verification and joins authenticated users to individual rooms (`user:<userId>`).
  - **Backend Dispatcher**: `backend/src/notifications/notification.service.ts` emits events `notification:new` (new notification payload + unread count) and `notification:unread_count` when events occur.
  - **Frontend Client**: `frontend/src/context/NotificationContext.tsx` establishes a socket connection using `socket.io-client` with the current access token, listens for `notification:new` and `notification:unread_count`, and triggers live state updates.

- **Expo Push Notifications**:
  - **Frontend Token Registration**: `frontend/src/lib/push-notifications.ts` configures Android notification channels and requests the device's Expo push token; `frontend/src/context/NotificationContext.tsx` dispatches this token via `POST /api/notifications/push-token`.
  - **Backend Push Dispatch**: `backend/src/notifications/expoPush.service.ts` batches tokens and delivers formatted push notifications using `expo-server-sdk`.
  - **Frontend Foreground Alerts**: `frontend/src/lib/push-notifications.ts` sets up `Notifications.setNotificationHandler` to show banners, sound, and badge counts when alerts arrive while the app is active.

# PART 2: FEATURE LIST

### 1. Phone OTP Authentication & Session Lifecycle
- **What it does:** Authenticates users via 6-digit SMS OTP, provides secure JWT sessions with automatic token rotation, and handles graceful logout.
- **How it's implemented:**
  - Backend generates 6-digit OTP, saves SHA-256 hash in `OtpVerification` with 5-minute expiry and 5-attempt limit.
  - On verification, returns active tokens for existing users or a 10-minute signed `signupToken` for new profiles.
  - Client handles 15-minute access tokens and 30-day refresh tokens through `SessionCoordinator` mutex rotation.
- **Backend files:**
  - `backend/src/auth/auth.routes.ts`
  - `backend/src/auth/controllers/auth.controller.ts`
  - `backend/src/auth/services/auth.service.ts`
  - `backend/src/auth/services/token.service.ts`
  - `backend/src/auth/auth.middleware.ts`
- **Frontend files:**
  - `frontend/src/api/auth.ts`
  - `frontend/src/api/client.ts`
  - `frontend/src/context/AuthContext.tsx`
  - `frontend/src/context/auth-events.ts`
  - `frontend/src/context/session-coordinator.ts`
  - `frontend/src/lib/token-storage.ts`
  - `frontend/src/app/(auth)/login.tsx`
  - `frontend/src/app/(auth)/verify-otp.tsx`
- **Endpoints / events:**
  - `POST /api/auth/send-otp`
  - `POST /api/auth/verify-otp`
  - `POST /api/auth/refresh`
  - `POST /api/auth/logout`

### 2. User Registration & Onboarding
- **What it does:** Allows newly verified phone numbers to complete registration by providing name, blood group, and optional location.
- **How it's implemented:**
  - Verifies presence of a valid `signupToken` in the authorization header.
  - Captures and validates user full name, blood group enum, and optional city, state, and geographic coordinates.
  - Creates the user record, marks `isPhoneVerified: true`, and immediately creates an active login session.
- **Backend files:**
  - `backend/src/auth/auth.routes.ts`
  - `backend/src/auth/controllers/auth.controller.ts`
  - `backend/src/auth/services/token.service.ts`

- **Endpoints / events:**
  - `POST /api/auth/signup`

### 3. User Profile Management & Security Alerting
- **What it does:** Enables users to view, edit, or delete their profile information and receive security notifications on changes.
- **How it's implemented:**
  - Authorizes requests against `res.locals.userId` ensuring users can only read or edit their own profile.
  - Validates coordinates and blood group enum values before updating PostgreSQL record.
  - Automatically sends an `ACCOUNT_SECURITY` notification to the user upon successful profile update.
- **Backend files:**
  - `backend/src/routes/user.routes.ts`
  - `backend/src/controllers/user.controller.ts`

### 4. Proximity-Based Donor Search
- **What it does:** Discovers matching blood donors filtered by blood group and sorted closest-first by geographic distance.
- **How it's implemented:**
  - Haversine formula calculates distance in kilometers (`calculateDistanceKm`) between requester and donor coordinates.
  - Strips donor phone numbers and coordinates from the response payload to protect user privacy prior to request acceptance.
  - Frontend checks cached device location with a 6-second active GPS timeout fallback and reverse geocoding.
- **Backend files:**
  - `backend/src/routes/user.routes.ts`
  - `backend/src/controllers/user.controller.ts`
  - `backend/src/lib/geo.ts`
  - `backend/src/auth/auth.middleware.ts`
- **Frontend files:**

### 5. Donation Request Creation with Urgency & Hospital Details
- **What it does:** Allows requesters to send targeted blood donation requests specifying urgency level and hospital destination.
- **How it's implemented:**
  - Persists `bloodGroup`, `hospitalName`, `hospitalCity`, and `urgency` (`CRITICAL`, `WITHIN_24H`, `SCHEDULED`).
  - Blocks self-requests and sets status to `PENDING`.
  - Enriches `DONATION_REQUEST` notification message with urgency and destination hospital name.
- **Backend files:**

### 6. Donation Request Decision & Contact Reveal
- **What it does:** Allows donors to accept or reject incoming requests, lets requesters cancel, and reveals phone/WhatsApp on acceptance.
- **How it's implemented:**
  - Enforces status transition rules: only pending requests can be accepted/rejected by donors or cancelled by requesters.
  - Counterparty phone number is masked and only provided in responses when status equals `ACCEPTED`.
  - Frontend renders urgency badge, destination container, and one-tap Call (`tel:`) or WhatsApp (`https://wa.me/`) buttons.
- **Backend files:**
